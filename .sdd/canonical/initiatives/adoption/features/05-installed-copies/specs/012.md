## 1. Intent & Context (*The Why*)

* **Problem Statement / Need:** Le câblage par symlink (spec 008) pose des paths machine absolus dans les repos cibles — non portables pour les collègues, bruités dans git, cassés en CI — et le merge `skills.paths` vers `node_modules/` lie la config de l'hôte au layout du package.
* **User / System Impact:** `sdd install` **copie** skills et agents aux chemins natifs des hôtes (`.opencode/skills/sdd-*/`, `.claude/{skills,agents}/`, `.agents/{skills,agents}/`) : zéro path local, zéro modification de `opencode.json`. Le refresh est géré par le journal : version du package ≠ version copiée ⇒ re-copie des cibles owned.
* **In Scope (What is added / modified):**
  * `src/cli/hosts.js` : plan de câblage par copie (arborescence skills/sdd-* + agents/*.md), refresh owned par comparaison de version journalisée, suppression des branches symlink + merge opencode + fallback EPERM copie (la copie est désormais le seul mécanisme).
  * Journal : cibles + `installedVersion` du package copieure (réutilise le motif du stamp 011) ; `--undo` inchangé (journal-based).
  * `src/cli/commands/install.js` : affichage du plan (copiés/refresh/skip) ; messages à jour.
  * Tests `test/install-command.test.js` : réécrits contre la copie.
  * README : section Installation mise à jour (copie, refresh auto, plus de note Windows symlink).
* **Out of Scope (Strict Exclusions):**
  * Hôtes nouveaux, connecteurs, détection (inchangés) ; `templates/` toujours non câblés (lus dans le package au runtime).

> *Clean Omission Note : Section 4.3 : sans objet — `node:fs/promises.cp` (Node ≥ 16.7), aucune dépendance.*

```mermaid
        H-->>U: warn + skip (INV-2)

    end

```

## 4. Detailed Specifications

### 4.1. Data Models & API Contracts

* **Destinations** : skills → `<host>/skills/sdd-*` (15 dossiers, contenus identiques au package) ; agents → `<host>/agents/*.md` ; hosts `claude`/`agents` → `.claude/**` / `.agents/**` ; host `opencode` → `.opencode/skills/**` (découverte native — plus de `skills.paths`).
* **Version** : source unique = `package.json` du module exécutant (même lecture que `update-check`).
* **Comparaison** : version journal ≠ version courante ⇒ refresh ; égal ⇒ no-op ; l'absence de version (journal legacy 008) ⇒ refresh par prudence.

### 4.2. UI & Interaction Specifications (CLI)

| État | Déclencheur | Comportement |
|---|---|---|
| **Install nominal** | hôtes détectés | Copies natives, journal à jour, récap "copied n files". |
| **Re-install même version** | journal version == courante | No-op idempotent. |
| **Re-install nouvelle version** | journal version ≠ courante | Refresh des cibles owned, message "version changed … refreshing". |
| **Cible étrangère** | présente sans journal | Warn + skip. |
| **Dry-run** | `--dry-run` | Plan affiché (copy/refresh/skip), rien d'écrit. |
| **Undo** | `--undo` | Retire les copies journalisées (et les dossiers parents vidés, jamais au-delà des cibles). |

## 6. Technical Watchouts & Anti-Patterns

* **Copie récursive** : `fs.cp(src, dst, { recursive: true })` — créer les dossiers parents ; ne jamais copier au-delà de `skills/` et `agents/` (les templates restent non câblés).
* **Refresh = remplacement** : re-copier un dossier owned doit écraser proprement (rm préalable du dossier cible owned, pas merge résiduel) — sinon des fichiers supprimés du package survivent.
* **Undo des dossiers** : retirer un dossier copié = rm -rf du dossier journalisé uniquement ; jamais `rm` récursif au-dessus (`.opencode/skills/` peut contenir d'autres skills utilisateur).
* **Windows** : la copie n'a plus de problème EPERM/symlink — supprimer le fallback et son doc ; le warning "re-run after update" devient le refresh auto.
* **`.claude/skills/sdd` vs `.claude/skills/sdd-*`** : l'ancien layout créait UN symlink `sdd` vers le dossier du package — le nouveau pose 15 dossiers individuels `sdd-<name>` ; le journal et l'undo doivent gérer ces noms distincts (pas de collision avec un éventuel ancien symlink `sdd` : warn + skip).
* **Legacy journals (008)** : entrées `kind: 'symlink'` / `opencode-path` — `--undo` doit les honorer encore (retirer un symlink journalisé) ; l'install nouveau régime les ignore pour le refresh.
* **Tests hermétiques** : tmpdir + pkgRoot du repo réel ; vérifier l'absence totale de symlink (lstat) et de modification d'`opencode.json`.

```gherkin
  @component
  Scenario: [INV-1] Install pose des copies natives

    Then les 15 skills sont copiés dans .opencode/skills/sdd-* et .claude/skills/sdd-*, les agents dans .claude/agents/ — aucun symlink, opencode.json inchangé, dry-run sans écriture

  @component
  Scenario: [INV-2] Refresh au changement de version
    Given un install journalisé en version A
    When le package "passe" en version B (pkg injecté) et re-install
    Then les cibles owned sont re-copiées, les étrangères warn+skip

  @component
  Scenario: [INV-2] No-op à version égale
    Given un install journalisé en version courante
    When re-install
    Then no-op, aucune re-copie

  Scenario: [INV-3] Undo exact des copies et des symlinks legacy
    Given un install (copies) puis un ancien journal 008 (symlink)

  @e2e
  Scenario: [INV-1..INV-3] Parcours complet
    Given un repo cible vierge
    When install → validate → re-install version bumpée → undo
    Then copies présentes puis rafraîchies puis retirées, opencode.json intact tout du long
```
